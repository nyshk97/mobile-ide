# チャット入力欄（composer）

## 概要・やりたいこと

端末画面の入力を、ChatGPT / Claude のスマホアプリと同じ「複数行のテキストエリアに書いて送信ボタンで送る」形にする。出力は今までどおり SwiftTerm の端末画面で見る（**入力はチャット、出力は端末**のハイブリッド）。

いまは端末をタップしてキーボードから 1 キーずつ PTY に流しているので、長い指示を書きにくい・送る前に読み返せない・貼り付けが不自然、という入力のつらさがある。Claude Code / Codex の UI や機能は一切変えず、入力欄だけ差し替えて解消する。出力を吹き出しで描く「本当のチャット UI」は Remote Control の再発明になるのでやらない。

## 前提・わかっていること

### 決定事項（/dig-lite）

- **既定はチャット入力欄。バーのボタンで「直接入力」に切り替えられる**。直接入力にすると入力欄が消えて端末がキーボードを持つ（今の挙動。シェルの tab 補完・vim / less・Enter なしで文字を打つ場面用）。モードはプロジェクト（tmux セッション名）ごとに記憶
- **送信は「本文 + Enter」の 1 種類だけ**。Enter なしで送りたい場面は直接入力に切り替える（送信ボタンの長押し等は付けない）
- **iOS キーボードの return は改行**。送信はボタン（ChatGPT アプリと同じ）
- **1 行でも常に bracketed paste で包む**（`ESC[200~ 本文 ESC[201~`）。相手アプリのモードは読まない。tmux がクライアント端末に対して常に bracketed paste を有効にし、ペイン側のモードに応じて包みを剥がす / 通すのを代行するため（下の実測）
- **下書きはプロジェクトごとに保持**。再接続・アプリ復帰・画面を閉じて開き直しても消えない
- **スラッシュコマンドのメニューは PTY に流すのをやめて入力欄に差し込む**（引数を続けて書ける）。Claude / Codex / gpull / gpush の起動系は今どおり PTY に即実行。直接入力モードのときはスラッシュも今どおり PTY に流す
- **画像添付の `@パス ` は入力欄のカーソル位置に差し込む**。直接入力モードのときは今どおり端末へ
- **配置は上から 端末 / キーボードバー / 入力欄**。キーボードバーの tab / ^C / 矢印 / ⏎ はどちらのモードでも PTY に直接届く（入力欄に文字を入れない）
- composer モードで端末をタップしても**キーボードは端末に移らない**（モードも切り替わらない。切替はバーのボタンだけ）。マウス追跡中（Claude Code など）のタップはクリックとして転送する今の挙動を保つ（1 回目で決定。スクロール中の誤タップでモードが勝手に変わるのを避ける）
- ただし端末は first responder にはなれる（タップすると入力欄のキーボードが閉じる。チャットアプリで本文をタップするとキーボードが引っ込むのと同じ）。**長押しの選択 → Copy** は first responder が前提（SwiftTerm の `longPress` は `becomeFirstResponder()` してから `UIMenuController` を出す）なので、端末のエラー文をコピーして入力欄に貼る動線を composer モードでも残すために、**`canBecomeFirstResponder` を塞ぐのではなく `inputView` を空の view に差し替えてキーボードだけ出さない**（2 回目で決定）。ハードウェアキーボードからの打鍵は端末に届くが、iPhone 単体では起きないので割り切る
- 送信した本文の控え（送信履歴・直前の本文を戻す操作）は今回の範囲に入れない。Claude Code の会話ログ側に残るので読み返せなくなるわけではない（1 回目で決定）
- 送信直後に接続が落ちて本文が消えたときの救済（送信の完了を待って空にする / 直前の送信を 1 件だけ持つ）も今回の範囲に入れない。`PTYSession.send` は enqueue だけで結果を返さない作りで、変えるなら別件（実装レビュー 1 回目で決定）
- 横向きは対象に残す（README の実機確認に横向きがある）。横向きでキーボードと 6 行の入力欄を出したとき端末の取り分がほぼ無くなる件は、入力欄の上限をコンテナ高で丸めるか端末に最小高さを持たせる別件（実装レビュー 1 回目で決定）

### 調査で確定した事実

- 入力経路は `surface.send(text:)` → SwiftTerm `send(txt:)` → `onInput` → `PTYSession.send`。画像添付の `@path ` は `session.send(Data)` を直接呼んでいる（`AttachmentFlow.send` 末尾）。composer の送信もここに乗せる
- **tmux 3.7c はクライアント端末（TERM=xterm-256color）に attach した時点で `ESC[?2004h` を送り、ペインのモードとは無関係に常にオンにする**（2026-09-06 に Air で pty から attach して実測。ペインが `?2004l` でも `?2004h` でもクライアントには `h` が 1 回届く）。クライアントから `ESC[200~ … ESC[201~` を送ると、**ペインが bracketed paste オフなら包みを剥がして本文だけ、オンなら包みごと**ペインに渡す（`cat -v` で `aaa` / `bbb` と `^[[200~aaa` / `bbb^[[201~` を確認）。つまりアプリ側は常に包めばよく、SwiftTerm の `bracketedPasteMode` を読む必要はない
- **Codex の TUI は bracketed paste の複数行を 1 入力として受ける**（2026-09-06 に Air で実測: tmux `set-buffer` + `paste-buffer -p` で 3 行を貼ると `› first line / second line / third line` と入力欄に入り、実行されない）。**`paste-buffer` は LF を CR に置換して貼る**ので、実測で通ったのは CR 区切り。アプリも本文の `\n` を `\r` に変換して包む（実端末の貼り付けと同じ形）。Claude Code も同じ（貼り付けは改行ごと入力欄に入る）。zsh 5.1+ も bracketed paste が既定で有効なので、素のシェルでも複数行は Enter まで実行されない
- 送信の末尾に付ける Enter は `\r`（`TerminalKey.enter` = `0x0d`、起動系ショートカットと同じ）。bracketed paste の**外**に付ける（中に入れると改行として入力欄に残る）
- 本文に `ESC`（0x1b）が入っていると包みを途中で閉じられる（端末ログの貼り付けで起きる）。送信時に `ESC` を落とす
- キーボードの first responder は端末 view（`terminalView.becomeFirstResponder()`）。SwiftTerm の `singleTap` はマウス追跡が無いときフォーカスが無ければ `becomeFirstResponder()` する（`WheelScrollingTerminalView.shouldForwardUnfocusedTap` はマウス追跡中だけクリック転送に切り替える）。composer モードでは端末 view の `inputView` を高さ 0 の view にしてキーボードを出さない（first responder にはなれるので長押し → Copy は生きる。`canBecomeFirstResponder` は SwiftTerm 1.20 で `open override` なので塞ぐことも可能だが使わない）。`TerminalScreen.wireUp` の `DispatchQueue.main.async { surface.showKeyboard() }` はモードで分ける
- `KeyboardBar.Action.toggleKeyboard` は端末の first responder を出し入れしている。composer モードでは「キーボードを閉じる」= 入力欄の focus を外す、に置き換える
- SwiftUI の `TextEditor` では要件が満たせない: カーソル位置への挿入 API が iOS 18 から（deployment target は 17.0）、IME の未確定文字を送信前に確定できない、placeholder が無い。**`UITextView` を `UIViewRepresentable` で包む**（`selectedRange` に挿入、送信前に `markedTextRange` があれば `unmarkText()`、`sizeThatFits` で 1〜6 行）
- 設定は `UserDefaults` に直接（`ConnectionSettings` の `connection.*`、`KnownHostStore`）。下書きとモードもプロジェクトごとのキーで同じように置く。プロジェクトを消しても残るが数十バイトなので掃除はしない
- 自走検証は `MOBILE_IDE_PRESS_KEYS`（`KeyboardBar.Action(name:)` を順に `perform`）と `MOBILE_IDE_TERMINAL_TYPE`（`session.send` 直接）。`runAutomation` は type → pressKeys → probe → … の直列。composer 経由の送信は別の入口を足し、Claude / Codex の起動（pressKeys）の後に発火できるよう待ち秒を持たせる
- キーボードバーの現在の並び: `[Claude] [Codex] [git ▾] [/ ▾] | tab ^C | ← ↓ ↑ → ⏎ | ⌨`

### 設計

```
Core/Terminal/TerminalSurface.swift     var showsKeyboard: Bool { get set } を追加（false なら端末が first responder でもキーボードを出さない）
Core/Terminal/SwiftTermSurface.swift    terminalView.inputView を nil（標準キーボード）/ 高さ 0 の view で切り替え、first responder 中なら reloadInputViews()
Core/Terminal/ComposerMessage.swift     送信する本文から PTY に流すバイト列を作る（純関数・テスト対象）
                                         static func bytes(for text: String) -> Data
                                           - 末尾の改行は落とす（return を押した後に送信、で空行を送らない）
                                           - ESC（0x1b）を落とす
                                           - \n → \r
                                           - ESC[200~ + 本文 + ESC[201~ + \r（1 行でも常に包む。tmux が相手に合わせて剥がす）
Core/Terminal/InputMode.swift           enum InputMode: String { case composer, direct }
Core/Terminal/ComposerStore.swift       @Observable。プロジェクトごとの下書きとモード（UserDefaults `composer.draft.<session>` / `composer.mode.<session>`）
                                         下書きは変わるたびに保存（onChange）。onDisappear だけでは閉じた直後の開き直しで新画面の onAppear が先に走り空を読む（実装中に実測）
Features/Terminal/ComposerView.swift    UITextView（UIViewRepresentable、1〜6 行で伸びる、placeholder）+ 送信ボタン（本文が空なら無効）。focus と「カーソル位置に挿入」を外から呼べる
                                         updateUIView は markedTextRange != nil の間と text が同じときは書き戻さない（変換中の未確定文字が消える / カーソルが先頭に飛ぶのを防ぐ）
Features/Terminal/KeyboardBar.swift     Action に .toggleInputMode を追加。⌨ の隣にモード切替ボタン（composer: "terminal" 系アイコン / direct: "text.bubble" 系）
                                         isKeyboardVisible の意味はモードで変わる（composer: 入力欄の focus / direct: 端末の first responder）
Features/Terminal/TerminalScreen.swift  レイアウト: VStack { TerminalSurfaceView / KeyboardBar / (mode == .composer ? ComposerView : nil) }
                                         perform:
                                           .shortcut(.slash) → composer なら入力欄に挿入、direct なら PTY
                                           .shortcut(起動系) → 常に PTY
                                           .key → 常に PTY
                                           .toggleKeyboard → モードに応じて focus を出し入れ
                                           .toggleInputMode → 切替。composer→direct で入力欄を隠し showsKeyboard=true にして端末に focus、逆は showsKeyboard=false にして入力欄に focus。下書きは残す
                                         send(): 未確定文字を確定 → ComposerMessage.bytes(...) を session.send → 下書きを空に。session.state != .running なら送らずアラート（添付と同じ文言の型）
                                         wireUp の showKeyboard → モードで分岐
Features/Terminal/AttachmentFlow.swift  結果の渡し先を closure 化: onTyped: (String) -> Void。TerminalScreen が composer なら接続状態に関係なく入力欄に挿入、direct なら今の分岐（running なら session.send、でなければアラート）
Core/App/LaunchOptions.swift            MOBILE_IDE_COMPOSE=<text>（DEBUG）: 入力欄に入れて送信する（`\n` は改行に展開）。MOBILE_IDE_COMPOSE_AFTER=<秒>（既定 1）で pressKeys の後に発火
                                         MOBILE_IDE_DRAFT=<text>（DEBUG）: 入力欄に入れるだけで送信しない（下書き保存の検証用）
                                         MOBILE_IDE_INPUT_MODE=direct|composer（DEBUG）: 起動時のモードを上書き（保存しない）
MobileIDETests/ComposerMessageTests.swift  bytes(for:) の形（包み・\r 区切り・末尾改行の除去・ESC の除去・空文字）
MobileIDETests/ComposerStoreTests.swift    下書きとモードの保存・復元がセッション名ごとに独立
```

目印行: `COMPOSE sent bytes=<n>`、`COMPOSE mode=<composer|direct>`（切替時と、画面を開いて保存値から復元したとき）、`COMPOSE inserted <text>`（スラッシュ / 添付の挿入時）、`COMPOSE draft restored n=<文字数>`（画面を開いて下書きを復元したとき）。
