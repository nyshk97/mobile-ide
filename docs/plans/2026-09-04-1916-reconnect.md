# 再接続（#7）

## 概要・やりたいこと

SSH が切れても、ユーザーに意識させずに同じ tmux セッションへ戻す。端末画面を開いたまま Wi-Fi が切れる・別アプリに切り替えて戻る・外出先で回線が変わる、といった場面で、端末の描画を消さずに黙って張り直し、`tmux new-session -A` で続きを表示する。

- 回線断を検出したら自動でバックオフ付きに張り直す
- フォアグラウンド復帰時と経路変更時に「まだ生きているか」を探り、死んでいれば張り直す
- 再接続中は端末を消さずに薄いバナーだけ出す
- 再接続の連打・多重化を防ぐ
- 切れた前の自分（古い tmux クライアント）を attach 時に蹴る

GitHub Issue: nyshk97/mobile-ide#7

## 前提・わかっていること

### 決定事項（/dig-lite）

- **自動再接続はトランスポート断とフォアグラウンド復帰時だけ**。tmux 内で `exit` / detach した正常終了（shell exited）は今どおり手動の「再接続」ボタンに残す。閉じたつもりのセッションを勝手に作り直さない
- **復帰時の生存判定は短い exec**。同じ接続で `true` を exec し、3 秒以内に応答が無ければ close して張り直す。生きていれば端末に一切触らない
- **attach は `tmux new-session -A -D`**。`-A` があるとき `-D` は `attach-session -d` と同じで、他のクライアントを全部 detach する（tmux 3.7c の man で確認）。切れた前の自分が残ってサイズが小さい方に合わされる・一覧の「接続中」が誤表示になる、を防ぐ。このセッションはアプリ専用なので Mac 側の端末が蹴られても許容
- sshd の `ClientAliveInterval` は #9 の Mac mini セットアップに入れる（Air は `#ClientAliveInterval 0` の既定のまま。切れた接続の sshd-session と tmux クライアントは長時間残る）

### 調査で確定した事実（Citadel 0.12.1 / NIOSSH）

- `SSHClient.isConnected`（`session.channel.isActive`）と `onDisconnect(perform:)` が public。`closeFuture` 完了で呼ばれる
- **keepalive は無い**。NIOSSH のグローバルリクエスト送信（`sendGlobalRequestMessage`）は internal で、public なのは TCP forwarding だけ。SSH レベルの ping は外から撃てない
- Citadel 自身の `SSHReconnectMode`（`connect(host:port:...reconnect:)`）はセッションを作り直すだけで PTY チャネルは戻らない。使わず自前で持つ（今の `connect(to:)` は `.never`）
- **回線が死んでも `withPTY` の inbound はエラーなしで普通に終わる**。`TTYHandler.handlerRemoved` が `.eof(nil)` を流すため、ストリームの終わり方だけでは shell exited と区別できない。終了時に `client.isConnected` を見て分類する（シェルが exit した場合は接続が生きている / 回線断なら `false`）
- `executeCommand` はチャネル作成に 15 秒のタイムアウトを持つ（`CitadelError.channelCreationFailed`）。生存判定はこれを待たず自前の 3 秒で打ち切る（`SSHConnection.firstToFinish` と同じ形）
- 無音の断（Wi-Fi → モバイル回線で IP が変わる等）では TCP の書き込みも即座には失敗しない（カーネルバッファに乗って再送タイムアウトまで数分）。キー入力の失敗に頼れないので、**経路変更（`NWPathMonitor`）とフォアグラウンド復帰を契機に探る**
- sshd 側のプロセスは `sshd-session: d0ne1s [priv]`（root）と `sshd-session: d0ne1s@ttysNNN`（ユーザー）。tmux クライアントの pid は `tmux list-clients -F '#{client_pid}'` で取れ、親（ログインシェル）の親が sshd-session
- 今の `TerminalTarget.launchCommand` は作業ディレクトリをクォートしていない（スペース入りの path で壊れる）。同じ行を触るのでここで直す。自走用の `~/mobile-ide` はチルダ展開に依存しているので、単引用符で包む方式ではなく **`[A-Za-z0-9_/.-]` 以外をバックスラッシュでエスケープし、先頭の `~` だけ素通し**にする

### 設計

```
Core/SSH/PTYSession.swift          State に reconnecting(attempt:) を追加、disconnected の理由を enum Disconnect に
                                   start で受けた connect クロージャと target を保持し、reconnect() / retryNow() / verifyAlive() を持つ
                                   client.onDisconnect と isConnected で終了理由を分類。write 失敗もトランスポート断扱い
Core/SSH/ReconnectPolicy.swift     バックオフの遅延（1, 2, 4, 8, 15, 15, …秒）と生存判定のタイムアウト（3 秒）。純関数でテスト
Core/App/NetworkPathObserver.swift NWPathMonitor の薄いラッパ。経路が satisfied になった / インターフェースが変わったときに通知
Features/Terminal/TerminalScreen.swift
                                   scenePhase が active に戻ったら session.verifyAlive()、経路変更でも同じ
                                   reconnecting は上端の薄いバナー（「再接続中… n 回目」+「今すぐ」）。shellExited は今の全面オーバーレイ
Features/Terminal/TerminalTarget.swift
                                   launchCommand を `tmux new-session -A -D -s <name> -c <escaped path>; exit` に。エスケープ関数を切り出してテスト
scripts/ssh-proxy.py               検証用の TCP 中継（127.0.0.1:2222 → 22）。SIGHUP で接続を全部切る、SIGUSR1 で凍結（ソケットは保ったまま中継停止）/ 解除
```

状態と遷移:

| 状態 | 入口 | 出口 |
|---|---|---|
| `connecting` | `start()` | 成功 → `running` / `ConnectFailure` → `failed` |
| `running` | PTY 確立 | inbound 終了 + `isConnected` → `disconnected(.shellExited)` / inbound 終了 + 切断 or write 失敗 or 探りの失敗 → `reconnecting(1)` / `close()` → `disconnected(.closed)` |
| `reconnecting(n)` | トランスポート断 | 遅延後に接続 → `running` / `.hostKeyMismatch` → `failed`（自動を止める）/ その他の失敗 → `reconnecting(n+1)` / `retryNow()` → 遅延を飛ばして接続 / `close()` → `disconnected(.closed)` |
| `disconnected(.shellExited)` | 正常終了 | 手動「再接続」→ `connecting` |
| `failed` | 接続失敗 | 手動「再試行」「新しい鍵を信用」→ `connecting` |

多重化の防止: 接続と再接続は 1 つの `task` だけが走る。`start` / `reconnect` は `connecting` / `running` / `reconnecting` 中なら無視。`verifyAlive` は `probing` フラグで 1 本に絞り、`running` 以外では何もしない（`reconnecting` の遅延待ちなら `retryNow()` に倒す）。

自走用の目印行: `TERMINAL lost <reason>` / `TERMINAL reconnecting attempt=<n> delay=<sec>` / `TERMINAL probe ok|dead` / `TERMINAL connected`（既存）。DEBUG の `MOBILE_IDE_PROBE_AFTER=<sec>` で接続後 N 秒に `verifyAlive()` を呼ぶ（scenePhase をシミュレータから起こせないため。scenePhase の配線自体は実機で見る）。

意図的に外すもの: 前面で無音断が起きて経路も変わらないケースの検出（keepalive が無いので次の探り契機まで気づかない。#9 の実測で問題になれば定期探りを足す）/ ホーム一覧の復帰時リフレッシュ（今も pull-to-refresh と画面遷移で更新される）。

### Phase 4: シミュレータでの自走検証 [AI🤖]

- [x] `scripts/ssh-proxy.py`: asyncio の TCP 中継。SIGHUP で既存接続を全部 close（listen は続ける）、SIGUSR1 で凍結トグル（ソケットを保ったまま両方向の中継を止める）。`--listen 2222 --target 127.0.0.1:22`
- [x] **回線断 → 自動再接続**: `TERMINAL_AUTORUN` で接続 → proxy に SIGHUP → `TERMINAL lost` → `reconnecting attempt=1 delay=1` → `TERMINAL connected`。`tmux display -p '#{session_created}'` が前後で同じ、`list-clients` が 1 件で `client_created` が断の後

- [x] **無音の断 → 探りで検出**: `MOBILE_IDE_PROBE_AFTER=5` で起動 → 接続直後に proxy に SIGUSR1（凍結）→ 5 秒後 `TERMINAL probe dead`（3 秒以内に判定）→ SIGUSR1 で解除 → `reconnecting` → `connected`。**凍結中は古い tmux クライアントが残っている**ので、再接続後の `list-clients` が 1 件なら `-D` が効いている証明（前に 2 件あった瞬間を `list-clients` で取っておく）
