# Citadel スパイク（#2）: iOS から Air に SSH して exec / PTY / SFTP を 1 接続で通す

## 概要・やりたいこと

SwiftNIO SSH ベースの [Citadel](https://github.com/orlandos-nl/Citadel) が iOS シミュレータ・実機でビルドでき、アプリ内生成の ed25519 鍵で公開鍵認証が通り、exec / PTY / SFTP の 3 チャネルを 1 接続で開けることを最小構成で確かめる。**ここで通らなければライブラリ選定（libssh2 系への切り替え）をやり直す**ための判断材料を出すのが目的で、UI の作り込みはしない。

ホストは Mac mini 到着まで MacBook Air（#1 で sshd + tmux を準備済み）。

GitHub Issue: nyshk97/mobile-ide#2

## 前提・わかっていること

### 決定事項（/dig-lite）

- **鍵はアプリ内で生成する**。CryptoKit の `Curve25519.Signing.PrivateKey` を Citadel の `.ed25519(username:privateKey:)` にそのまま渡す。OpenSSH 形式の秘密鍵ファイルは使わない（Issue 本文の「ssh-keygen で作り gitignore したファイルから読む」は本 plan で上書きする）
- 秘密鍵の保存は **UserDefaults に一時置き**（raw 32 バイトの seed）。Keychain への移行は #4
- 公開鍵は **OpenSSH 形式の 1 行**（`ssh-ed25519 <base64> mobile-ide-dev`）で画面に表示し、コピーして Air の `authorized_keys` に貼る
- **スパイク範囲は exec + PTY + SFTP を 1 接続で順に実行**。exec は `echo hello`、PTY は `withPTY` で `tmux -V` を流して出力を受ける、SFTP は `openSFTP` → `getRealPath(".")`。SwiftTerm は入れない
- **ホスト鍵検証は `.acceptAnything()`**。known_hosts 相当の固定は #4 で決める
- **ホスト名・ユーザー名は画面のテキスト欄**。シミュレータは `127.0.0.1`、実機は `tsubasanoMacBook-Air-4.local`
- **`NSLocalNetworkUsageDescription` を Info.plist に追加**（LAN の `.local` へ接続するために必要。Tailscale 経由の 100.x になれば不要だが Air 相手の開発中は必須）

### 調査で確定した事実（Citadel 0.12.1、2026-04-04 リリース）

- `Package.swift` は swift-tools 5.9、platforms は `.iOS(.v17)` / `.macOS(.v14)`。本プロジェクト（iOS 17、SWIFT_VERSION 5.10、Xcode 26.6）にそのまま入る
- 依存: `Wellz26/swift-nio-ssh` 0.3.4（フォーク）、swift-nio 2.81+、swift-crypto 3.12.3+、BigInt、swift-log
- 認証: `SSHAuthenticationMethod.ed25519(username:privateKey: Curve25519.Signing.PrivateKey)`。password / rsa / p256 / p384 / p521 / custom もある
- 接続: `SSHClient.connect(to: SSHClientSettings(host:authenticationMethod:hostKeyValidator:))`。`reconnect:` 引数付きの overload あり（`.never` / `.once` / `.always`）。`isConnected`、`onDisconnect(perform:)`、`close()`
- exec: `executeCommand(_:maxResponseSize:mergeStreams:)` → ByteBuffer。`executeCommandStream` / `executeCommandPair` で stdout/stderr 分離
- PTY: `withPTY(SSHChannelRequestEvent.PseudoTerminalRequest(...)) { ttyOutput, stdinWriter in }`。`TTYOutput` は AsyncSequence、`TTYStdinWriter.write(ByteBuffer)` と `changeSize(cols:rows:pixelWidth:pixelHeight:)`（WindowChangeRequest）
- SFTP: `openSFTP()` → `SFTPClient`、`getRealPath(atPath:)` など
- exec / PTY / SFTP はいずれも同じ session の `sshHandler.createChannel` で開くので、1 接続で多重化できる
- exec チャネルは `.zshrc` を読まない（#1 で実測。`tmux` は `PATH=/opt/homebrew/bin:$PATH` 前置きが必要）。PTY 経由の対話シェルは `.zshrc` を読む

### プロジェクト側の事実

- XcodeGen（`project.yml` が source of truth、`.xcodeproj` は gitignore）。SPM パッケージはまだ 1 つも無い。`Package.resolved` は gitignore 済みなので、再現性は `project.yml` で `exactVersion: 0.12.1` を指定して担保する
- 画面は `MobileIDE/Features/Home/HomeView.swift` のプレースホルダ 1 枚だけ
- `mise run build`（シミュレータ）/ `mise run device-build`（実機、`-allowProvisioningUpdates` 付き）。シミュレータ起動は `xcrun simctl launch`、実機は `xcrun devicectl device process launch`。どちらも `--console` で stdout を Mac 側に流せるので、**スパイクの結果は画面表示に加えて `print` でも出し、AI が自走で読めるようにする**
- シミュレータのクリップボードは `xcrun simctl pbpaste booted` で Mac 側から読める → 公開鍵の `authorized_keys` 登録をシミュレータ経路では AI が自走できる

### 判断基準（スパイクの合否）

| 項目 | 合格 | 不合格時 |
|---|---|---|
| ビルド | シミュレータと実機の両方で Citadel をリンクしてビルドが通る | Swift/NIO のビルドエラーが解消できなければライブラリ変更を検討 |
| 認証 | アプリ内生成の ed25519 鍵で publickey 認証が通る | 鍵の wire 形式か Citadel 側の問題を切り分け、直せなければ変更 |
| exec | `echo hello` の stdout に `hello` | |
| PTY | `tmux -V` の出力に `tmux 3.` が含まれる | |
| SFTP | `getRealPath(".")` がホームディレクトリの絶対パスを返す | |
| 多重化 | 上記 3 つが同じ `SSHClient` インスタンスで順に成功する | チャネルごとに接続し直す設計に倒す（README の構成図を修正） |
