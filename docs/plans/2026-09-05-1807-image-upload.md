# 画像添付（#8）

## 概要・やりたいこと

写真やスクショを Claude Code に渡す。端末画面から写真ピッカーで画像を選ぶと、SFTP でホストの `~/.claude/uploads/` に置き、端末に `@<絶対パス> ` を流し込む。Claude Code のプロンプトにそのまま入るので、続けて指示を打てば Claude が画像を読める。

- PhotosPicker で画像を選ぶ（最大 4 枚）
- SFTP で `~/.claude/uploads/` に置く（無ければ作る）
- ファイル名はタイムスタンプ + バッチ内の連番で重複しない
- 端末に `@<path> ` を流し込む（複数なら `@a @b `）
- 転送中の進捗とエラーの表示

GitHub Issue: nyshk97/mobile-ide#8

## 前提・わかっていること

### 決定事項（/dig-lite）

- **アップロードは専用の SSH 接続で行う**。選んだときだけ `SSHConnection.connect` で別接続を張り、SFTP で置いて閉じる。端末の接続（`PTYSession`）は再接続で入れ替わるので相乗りしない。接続オーバーヘッドは Tailscale 経由で 1 秒弱。README の「1 接続に複数チャネル」の図は実態に合わせて直す
- **画像は長辺 2048px に縮小**。写真（HEIC / JPEG）は JPEG 品質 0.85、スクショ（PNG）は PNG のまま（UI の小さな文字を滑らせない）。iPhone の写真は HEIC で Claude Code の Read が読めないので変換は必須。PNG にも同じ縮小を掛ける（スクショだけ閾値を変える案は見送り。dig-lite の決定どおり）
- 複数枚の途中失敗: **成功した分だけ流し込み、失敗した枚数をアラートに出す**（全部やめない。変換で落ちた枚も同じ扱い。`ImageUploader` の戻りは「成功したパスの配列 + 最初の失敗」）（1 回目で決定）。再接続後に流し込み直す導線（成功パスを保持して再送するボタン）は今回の範囲に入れない（2 回目で決定）
- 許可プロンプトが出た場合の逃げ道: **dotfiles 管理の `~/.claude/settings.json`（symlink）で許可する**。`permissions.allow` の `Read(...)` と `permissions.additionalDirectories` のどちらが効くかは Phase 0 で両方試し、効いた方を書式ごとここに書き戻す。dotfiles 側の差分は人間がコミットする（コミットされないと Mac mini に載らない）。プロジェクト配下に置く案はリポジトリごとに gitignore が要るので採らない（2 回目で決定、3 回目で書式を保留に）
- 転送中の表示: **再接続バナーと同じ上端の薄いバナー**（「送信中 n / N」+ 進捗バー）で端末を塞がない。キャンセルは今回の範囲に入れない（1 回目で決定）

### 調査で確定した事実

- Citadel の SFTP（#2 のスパイクで実機・シミュレータとも通過）: `client.openSFTP()` → `SFTPClient`。`getRealPath(atPath: ".")` がホームの絶対パス、`withFile(filePath:flags:) { file in try await file.write(buffer, at: offset) }`。フラグは `[.write, .create, .truncate]`（スパイクで実際に通したのは `openSFTP` と `getRealPath` だけ。`withFile` / `write` は Phase 1 で実物で確かめる）
- `SFTPFile.write` は内部で 32,000 バイトずつ直列に送る（swift-nio-ssh の制約）。1MB なら 32 往復で、Tailscale の RTT 30ms なら 1 秒程度。進捗は自分で 256KB ごとに `write(_:at:)` を呼んで出す
- `PhotosPicker`（SwiftUI, iOS 16+）は権限不要。`PhotosPickerItem.loadTransferable(type: Data.self)` で元バイト列（HEIC のまま）。PNG かどうかはピッカーの型情報でなく**データ自身（`CGImageSourceGetType` の UTI）で判定**し、ピッカー経路と DEBUG のファイル経路で同じコードを通す
- 縮小と向きの正規化は ImageIO の `CGImageSourceCreateThumbnailAtIndex`（`kCGImageSourceThumbnailMaxPixelSize: 2048`、`kCGImageSourceCreateThumbnailWithTransform: true`、`kCGImageSourceCreateThumbnailFromImageAlways: true`）。2048 以下の画像はそのまま再エンコード
- Claude Code の `@` メンションはプロンプトに `@/absolute/path.jpg ` と打てば画像も読める想定。`~` の展開は当てにせず絶対パスを流す（`getRealPath(".")` で取ったホーム + `/.claude/uploads/<name>`）。ただし **対話 TUI は `@` でファイル補完のオーバーレイが開く**ので、`PTYSession.send` で 1 文字列を流し込んだときに素のパスとして残るか、cwd 外の絶対パスで許可プロンプトが出ないかは未確認。**Phase 0 で tmux 上の実際の経路で確かめてから送る文字列の形と置き場所を確定する**
- `~/.claude/uploads/` の作成は SFTP の `createDirectory`（既存だと失敗する・`getAttributes` の挙動もスパイクで未確認）でなく、同じ接続の `executeCommand("/bin/mkdir -p <絶対パス>")` で行う（冪等。exec は `.zshrc` を読まないので絶対パス）
- `PTYSession.send(Data)` で端末に文字列を流せる（`running` 以外では捨てられる）。流し込み前に状態を見て、`running` でなければ「端末に接続してから」とエラーにする

### 設計

```
Core/SSH/ImageUploader.swift        struct UploadItem { data: Data, ext: "jpg" | "png" } の配列を受け取り、専用接続を張って mkdir -p → SFTP で順に置く。
                                   非 throws で (paths: 成功したパスの配列, failure: ConnectFailure?) を返す。進捗コールバック（index, fraction）。
                                   `~/.claude/uploads` は getRealPath(".") + "/.claude/uploads"。
                                   SSHConnection.connect の ConnectFailure（hostKeyMismatch を含む）は包まずそのまま failure に入れ、SFTP の失敗だけ .other に包む
Core/Media/ImageTranscoder.swift    Data（HEIC/JPEG/PNG）→ UploadItem。長辺 2048、PNG は PNG のまま、それ以外は JPEG 0.85。
                                   nonisolated な純関数で、呼び出し側は Task.detached で回す（12MP × 4 枚を MainActor で回すと端末描画が止まる）
Core/App/LaunchOptions.swift        DEBUG: MOBILE_IDE_UPLOAD_FILE=<path>[,<path>…]（カンマ区切りで複数枚。running の MOBILE_IDE_UPLOAD_AFTER 秒後（既定 0）に同じ経路で上げて流し込む）
Features/Terminal/AttachmentButton.swift  PhotosPicker（maxSelectionCount 4、filter .images）。選択 → 変換 → アップロード → send
Features/Terminal/TerminalScreen.swift    ナビゲーションバー右にボタン。転送中は再接続と同じ上端バナー（「送信中 n / N」+ ProgressView(value:)）、失敗は alert
```

ファイル名: `yyyyMMdd-HHmmss-<バッチ内の連番>.jpg|png`（端末のローカル時刻。同一バッチ内は連番で衝突しない）。流し込む文字列は Phase 0 で確定した形（既定は `"@\(path) "` を枚数分連結）。

目印行（自走用）は**変換とアップロードをまとめる呼び出し側（AttachmentButton の処理）が出す**（`ImageUploader` は転送しか知らないので数を持たない）: `UPLOAD start n=<選択枚数>` / `UPLOAD progress <i>/<N>`（`uploadProgress` を更新する側が出す。バナーの配線の証拠）/ `UPLOAD put <path> <bytes>` / `UPLOAD done n=<成功> failed=<変換失敗 + 転送失敗>` / `UPLOAD failed <reason>`（1 枚も置けなかった・接続できなかった）/ `UPLOAD typed <text>`。アラートの枚数も同じ合算値。

意図的に外すもの: 動画・ファイル一般の添付、アップロード済み画像の一覧・削除、`~/.claude/uploads/` の掃除（Mac 側で `find -mtime +7 -delete` を cron に入れるなら #9 で）。
